applab is installed in namespace {{ include "applab.namespace" . }}.

{{ $console := include "applab.consoleURL" . -}}
{{ if $console -}}
Reach it at:

    {{ $console }}

{{ else -}}
It is reachable only from inside the cluster: this release has no Ingress, and
no apps.baseDomain to put the console on the gateway under. Forward a port:

    kubectl -n {{ include "applab.namespace" . }} port-forward svc/{{ include "applab.fullname" . }} 8080:{{ .Values.service.port }}

{{ end -}}
Set up the CLI:

    export APPLAB_URL={{ if $console }}{{ $console }}{{ else }}http://localhost:8080{{ end }}
    export APPLAB_KEY=<a key from the release's Secret>

Then, from any project:

    applab push myshop

{{/*
Whether the apps have hostnames depends on apps.baseDomain, not on whether
applab itself has an Ingress: the two are separate settings, and an install can
serve the console plainly while still giving apps hostnames, or the reverse.
*/}}
{{ if .Values.apps.baseDomain -}}
Apps are published through the Istio gateway {{ .Values.deploy.gateway }}. That
gateway has to exist and have a listener for {{ .Values.apps.baseDomain }}; a
missing one shows up as an app that deploys and reports healthy but cannot be
reached from outside the cluster.

{{ if .Values.apps.pathPrefix -}}
Apps share one host and are told apart by path: an app with id "shop" is served
at {{ .Values.apps.baseDomain }}{{ .Values.apps.pathPrefix }}/shop.
{{ else -}}
Each app takes its own subdomain: an app with id "shop" is served at
shop.{{ .Values.apps.baseDomain }}.
{{ end -}}
{{ else -}}
Note: apps.baseDomain is empty, so the apps you deploy are reachable only inside
the cluster. Set apps.baseDomain to give them hostnames.

{{ end -}}
{{ if .Values.build.enabled -}}
Builds run as Kubernetes Jobs with BuildKit rootless. That needs the cluster's
nodes to permit unprivileged user namespaces; if builds fail immediately with a
permissions error, see the chart README's prerequisites. `build.rootless=false`
is the fallback, at the cost of running builds privileged.

Images are pushed to: {{ .Values.build.registry }}

{{ else -}}
The build pipeline is disabled, so applab stores source and deploys, but cannot
build an image from it. `applab push` will say so. To enable it, set
build.enabled=true and build.registry.

{{ end -}}
Read what this deployment is, and every endpoint it serves:

    curl -s {{ if $console }}{{ $console }}{{ else }}http://localhost:8080{{ end }}/api/v1/describe

That call needs no key — it is how a caller finds out what this is before it has
one. The same answer is fuller with a key, which is what lets it name the apps
that key reaches.
